# Ae.solator Master Engineering Directive

This directive is a hard rule for `aesolator`.

The workspace Black Diamond execution layer at
`/data/data/com.termux/files/home/.codex/rules/OMEGA_BLACK_DIAMOND_MONOLITH.md`
is mandatory when `aesolator` participates in Chapter 2 donor-transfer,
graphics/runtime routing, package-truth, device-proof, or provenance closure.
It requires hostile self-audit, source-first compile stitching across the
product line, donor arbitration outcomes, and durable evidence-ledger
checkpoints.

Every UI/runtime-binding change, route decision, rootfs/imagefs path, provider
selection, command bridge, forensic-log action, config edit, and device-runtime
conclusion must be handled as an app/product-surface class problem until
evidence proves it is isolated.

## Enforced Repair Policy

Advisory-only behavior is forbidden for technical tasks whenever direct
remediation is possible.

For this app/runtime repository, default execution is:

1. investigate;
2. identify root cause;
3. search UI, lifecycle, runtime binding, Contents, rootfs/imagefs,
   provider routing, command bridges, logs/forensics, tests, configs, docs,
   and tooling for the defect class;
4. implement a systemic fix;
5. propagate it to materially related locations;
6. update tests, configs, docs, tooling, and integration contracts where
   needed;
7. verify.

Do not stop at diagnosis, recommendations, or manual steps when the app tree
can be repaired directly.

## Engineering Identity

Ae.solator work is mandatory systemic remediation, not consultation.
Choose app/runtime contract repair over UI-only patching, explicit provider and
path contracts over hidden defaults, stable shared helpers over repeated local
conditionals, and verified device behavior over visual assumptions.
Prefer shared utilities, centralized guards, common adapters, common validation
layers, common error/retry/timeout semantics, common tracing/observability
patterns, and common configuration conventions when safe unification reduces
app/runtime risk.

## Contract

- Repair root causes and defect classes, not the nearest UI/runtime symptom.
- Treat app behavior as an integrated product surface:
  UI, lifecycle, Contents, rootfs/imagefs paths, provider routing, runtime
  selection, command bridges, prefix pack, logs/forensics, packaging
  consumers, and device runtime behavior.
- Do not patch one class, one UI path, one container path, one library address,
  one provider route, or one log line when the pattern plausibly exists across
  app/runtime/package seams.
- Evidence must precede edits:
  source proof, device proof, app forensic JSONL/crash proof, rootfs/package
  proof, runtime stream proof, and donor/upstream comparison for transferred
  logic.
- For broad Gradle/build, parser, donor, rootfs/package, or runtime probes,
  wait for a real stopping point before declaring the frontier or repairing
  logs unless the harness itself is the blocker.
- A complete harvested log/evidence set is the source of truth for a wave.
  Classify by owner surface and fix the whole reflected union.
- For a broad build wave, the repair surface is the entire harvested log or
  evidence set, not the visible tail or first failing excerpt. Whole-wave
  closure requires covering every warning/error family reflected in that full
  harvest before the next pass.
- When the user asks for `%` or `как там` during an active build/runtime wave,
  answer with the global percent of remaining work across the active frontier,
  not local tail progress alone. If the denominator is estimated, mark that
  explicitly and state the basis.
- If the user explicitly requires a graphics/XServer donor transfer to land as
  one batch without intermediate builds, keep Java/Kotlin, JNI/native,
  bundled assets, XServer/GLX seams, runtime env/forensics, donor source, and
  shipped binary evidence under one closure surface until the lane is
  reconciled.
- For that graphics/XServer lane, source-only parity is insufficient.
  Maintain a deterministic reverse-engineering dossier over shipped renderer
  binaries:
  dynamic dependencies, exported JNI symbols, hard-coded package/cache paths,
  Vulkan-loader strings, and hex-anchored offsets where they explain route
  ownership or runtime behavior.
- For that lane, do not reopen `gradlew`, APK install, or device validation in
  the middle of the transfer.
- Where shipped native binaries are part of the ownership surface, maintain a
  deterministic reverse-engineering dossier over sections, imports/exports,
  strings, symbol surface, and hex-anchored offsets when they materially
  explain runtime behavior or route ownership.
- No fake completion:
  do not claim closure without root cause, affected surface, systemic fix,
  verification, residual risk, and hardening follow-up.
- If environment limits prevent automatic repair, prepare the exact patch or
  replacement content and state the blocked action explicitly.
- Hidden app/runtime/device contracts should be made explicit and testable
  where practical.
- Use safe deep research against Android, Wine, donor, package, graphics,
  security, and runtime sources when it materially improves app/runtime
  correctness.
- Security-first app work is mandatory:
  protect secrets, app-private data, device logs, package trust, network
  boundaries, permissions, rollback safety, and telemetry/logging hygiene.
- If context is insufficient, expand across UI, lifecycle, runtime binding,
  Contents, rootfs/imagefs, provider routing, command bridges, forensics,
  tests, configs, scripts, CI, package consumers, device state, and donor
  history before editing.

- No advice-only completion when app remediation is possible.
- No UI symptom masking while runtime/rootfs/provider contracts remain broken.
- No one-path repair when the same defect class spans containers, shortcuts,
  launch routes, Contents, forensics, or package consumers.
- No completion claim without root cause, affected surface, systemic fix,
  verification, residual risk, and hardening follow-up.
- No simulated verification, simulated device proof, or simulated access to
  logs/artifacts that were not actually checked.
